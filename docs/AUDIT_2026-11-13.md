### 🔴 S1 — DK लाइव का Terminal (सबसे ज़रूरी)

**क्या है:** DK लाइव (Gemini) `terminal` tool से फ़ोन पर असली shell (`/system/bin/sh -c`) चला सकता है (`GeminiLiveTools.kt:381` → `DkaiShell.liveTool`)।

**गड़बड़ी 1 — पुष्टि AI के हाथ में:**
```kotlin
val ok = args.optBoolean("confirmed", false)
if (DkaiTerm.risky(cmd) && !ok) return "CONFIRM_NEEDED: ..."
```
"हाँ" की जाँच ऐप नहीं करता। AI पहली बार में ही `confirmed=true` भेज दे, तो कमांड बिना पूछे चल जाती है। AI गलती से भी ऐसा कर सकता है, या किसी वेब पेज, notification या आने वाले मैसेज में छिपे निर्देश (prompt injection) के कहने पर भी।

**गड़बड़ी 2 — खतरनाक कमांड की जाँच आसानी से बायपास:** मैंने वही regex चलाकर देखा:

| कमांड | `risky()` पकड़ता है? |
|---|---|
| `rm -rf x` | ✅ हाँ |
| `toybox rm -rf /sdcard/DCIM` | ❌ नहीं |
| `sh -c 'rm -rf x'` | ❌ नहीं |
| `env rm -rf x` / `command rm -r x` / `busybox rm x` | ❌ नहीं |
| `cp /dev/null important.txt` (फ़ाइल खाली) | ❌ नहीं |
| `cat a \| tee b` (ऊपर लिखना) | ❌ नहीं |

**असर:** `MANAGE_EXTERNAL_STORAGE` मिली हो तो पूरी फ़ोन storage (फ़ोटो, Download, Documents) मिट सकती है या पढ़कर AI को भेजी जा सकती है।

**कैसे ठीक करें:**
1. पुष्टि **ऐप के अंदर** हो: risky कमांड पर ऐप खुद dialog या notification दिखाए ("यह कमांड चलाऊँ? हाँ/ना"), और सिर्फ़ उपयोगकर्ता के बटन दबाने पर चले। `confirmed` वाला argument हटा दें या उसे ignore करें।
2. Blocklist की जगह **allowlist** रखें: DK लाइव से सिर्फ़ पढ़ने वाली कमांड (`ls`, `cat`, `pwd`, `git status`, `grep`…) बिना पूछे चलें, बाकी सब पर पुष्टि।
3. Shell का काम करने का फ़ोल्डर (`dir`) DKAI workspace तक सीमित करें, और `/sdcard` व `/data/data/com.dk.assistant/shared_prefs` जैसे path वाली कमांड रोकें।
4. Test जोड़ें: `toybox rm`, `sh -c`, `env`, `cp`, `tee` वाले मामले `risky = true` हों, और `confirmed=true` होने पर भी ऐप की पुष्टि के बिना कमांड न चले।

### 🟠 S2 — Preview WebView को फ़ाइलें पढ़ने की खुली छूट
`DkaiPanels.kt:912`: `allowFileAccess = true; allowFileAccessFromFileURLs = true`। लोकल सर्वर न चले तो HTML `file://` से खुलती है। तब उस पेज का JavaScript (जैसे GitHub से clone किया पराया प्रोजेक्ट) फ़ोन की दूसरी फ़ाइलें पढ़कर इंटरनेट पर भेज सकता है।
**सुधार:** `allowFileAccessFromFileURLs = false`; `file://` वाला रास्ता हटाकर सिर्फ़ `WebViewAssetLoader` या लोकल सर्वर इस्तेमाल करें (Forge/Studio में यह पहले से सही है)।

### 🟠 S3 — लोकल सर्वर पर CORS `*`
`DkaiServer.kt:86` हर जवाब में `Access-Control-Allow-Origin: *` भेजता है। सर्वर चलते समय फ़ोन के browser में खुली **कोई भी वेबसाइट** `http://localhost:8080/...` से प्रोजेक्ट की फ़ाइलें पढ़ सकती है।
**सुधार:** यह header हटा दें (Preview उसी origin से चलता है, उसे इसकी ज़रूरत नहीं)। चाहें तो एक random token वाला path (`/t/<token>/…`) भी जोड़ दें, और Preview बंद होने पर सर्वर अपने-आप बंद हो।

### 🟠 S4 — ताकतवर permissions + AI
ऐप के पास `MANAGE_EXTERNAL_STORAGE`, `SEND_SMS`, `CALL_PHONE`, `READ_CALL_LOG`, `READ_CONTACTS`, `ANSWER_PHONE_CALLS`, Accessibility, Notification listener, `WRITE_SECURE_SETTINGS` सब हैं। AI बाहर से आया text (वेब, notification, मैसेज) पढ़ता है, इसलिए prompt injection से ये permissions गलत काम में इस्तेमाल हो सकती हैं।
**सुधार:** पैसे भेजना, SMS, कॉल, फ़ाइल मिटाना और मैसेज भेजना जैसे काम हमेशा ऐप की अपनी पुष्टि से हों, AI की हाँ से नहीं। बाहर के text को prompt में "अविश्वसनीय डेटा" बताकर अलग रखें।
**ध्यान दें:** Google Play इन permissions (SMS, Call log, पूरी storage, Accessibility का दूसरा इस्तेमाल) पर कड़े नियम रखता है। अभी ऐप GitHub Releases से बँटता है, इसलिए दिक्कत नहीं, लेकिन Play पर डालना हो तो बड़ा काम होगा।

### 🟡 S5 — Logcat
`DKLog.kt:26` हर संदेश बिना छिपाए `Log.d` में भी लिखता है, release build में भी। USB debugging चालू हो तो पढ़ा जा सकता है।
